Sequence blocks
       A line starting ~SEQ(var, start, step, end) will cause the remainder of the line to be processed multiple times, with the variable $var set initially to start, and then $var will
       be incremented by step repeatedly, terminating when it is greater than end. step may be omitted, in which case it defaults to 1 or -1, depending on whether end is greater or less
       than start. start may also be omitted, in which case it defaults to 1 if end > 0 or -1 if end < 0. so, for example:

           ~SEQ(SUBNET, 0, 3) ip_address 10.0.$SUBNET.1

           would produce:
               ip_address 10.0.0.1
               ip_address 10.0.1.1
               ip_address 10.0.2.1
               ip_address 10.0.3.1

       There can be multiple ~SEQ elements on a line, so for example:

           $VI4= \
           vrrp_track_file offset_instance_4.${IF}.${NUM}.${ID} { \
               file "${_PWD}/679/track_files/4.${IF}.${NUM}.${ID}" \
               weight -100 \
           } \
           vrrp_instance vrrp4.${IF}.${NUM}.${ID} { \
               interface bond${IF}.${NUM} \
               use_vmac vrrp4.${IF}.${NUM}.${ID} \
               virtual_router_id ${ID} \
               priority 130 \
               virtual_ipaddress { \
                   10.${IF}.${NUM}.${ID}/24 \
               } \
               track_file { \
                   offset_instance_4.${IF}.${NUM}.${ID} \
               } \
           }

           ~SEQ(IF,0,7) ~SEQ(NUM,0,31) ~SEQ(ID,1,254) $VI4

           will produce 65024 vrrp instances with names from vrrp4.0.0.1 through to
           vrrp4.7.31.254.
