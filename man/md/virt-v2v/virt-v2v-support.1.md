# Name

virt-v2v-support - Supported hypervisors, virtualization management
systems and guests in virt-v2v

<a name="description"></a>

# Description

.IX Header "DESCRIPTION"
This page documents which foreign hypervisors, virtualization
management systems and guest types that **virt-v2v**\|(1) can support.

Note this page applies to upstream virt-v2v from
http://libguestfs.org and in downstream distributions of virt-v2v
sometimes features are intentionally removed, or are present but not
supported.

<a name="hypervisors-input"></a>

### Hypervisors (Input)

.IX Subsection "Hypervisors (Input)"

* VMware ESXi  
  .IX Item "VMware ESXi"
  Must be managed by VMware vCenter ≥ 5.0 unless \s-1VDDK\s0 is available.
* \s-1OVA\s0 exported from VMware  
  .IX Item "OVA exported from VMware"
  OVAs from other hypervisors will not work.
* \s-1VMX\s0 from VMware  
  .IX Item "VMX from VMware"
  \s-1VMX\s0 files generated by other hypervisors will not work.
* \s-1RHEL 5\s0 Xen  
  .IX Item "RHEL 5 Xen"
* \s-1SUSE\s0 Xen  
  .IX Item "SUSE Xen"
* Citrix Xen  
  .IX Item "Citrix Xen"
  Citrix Xen has not been recently tested.
* Hyper-V  
  .IX Item "Hyper-V"
  Not recently tested.  Requires that you export the disk or use
  **virt-p2v**\|(1) on Hyper-V.
* Direct from disk images  
  .IX Item "Direct from disk images"
  Only disk images exported from supported hypervisors, and using
  container formats supported by qemu.
* Physical machines  
  .IX Item "Physical machines"
  Using the **virt-p2v**\|(1) tool.

<a name="hypervisors-output"></a>

### Hypervisors (Output)

.IX Subsection "Hypervisors (Output)"
\s-1QEMU\s0 and \s-1KVM\s0 only.

<a name="virtualization-management-systems-output"></a>

### Virtualization management systems (Output)

.IX Subsection "Virtualization management systems (Output)"

* OpenStack  
  .IX Item "OpenStack"
* Red Hat Virtualization (\s-1RHV\s0) 4.1 and up  
  .IX Item "Red Hat Virtualization (RHV) 4.1 and up"
* Local libvirt  
  .IX Item "Local libvirt"
  And hence **virsh**\|(1), **virt-manager**\|(1), and similar tools.
* Local disk  
  .IX Item "Local disk"

<a name="guest-firmware"></a>

### Guest firmware

.IX Subsection "Guest firmware"
\s-1BIOS\s0 is supported for all guest types and hypervisors.

VMware allows you to present \s-1UEFI\s0 firmware to guests (instead of the
ordinary \s-1PC BIOS\s0).  Virt-v2v can convert these guests, but requires
that \s-1UEFI\s0 is supported by the target hypervisor.

Currently \s-1KVM\s0 supports \s-1OVMF,\s0 an open source \s-1UEFI\s0 firmware, and can run
these guests.

Since \s-1OVMF\s0 support was only recently added to \s-1KVM\s0 (in 2014/2015), not
all target environments support \s-1UEFI\s0 guests yet:

* \s-1UEFI\s0 on libvirt, qemu  
  .IX Item "UEFI on libvirt, qemu"
  Supported.  Virt-v2v will generate the correct libvirt \s-1XML\s0 (metadata)
  automatically, but note that the same version of \s-1OVMF\s0 must be
  installed on the conversion host as is installed on the target
  hypervisor, else you will have to adjust paths in the metadata.
* \s-1UEFI\s0 on OpenStack  
  .IX Item "UEFI on OpenStack"
  Supported since virt-v2v ≥ 1.43.2.
* \s-1UEFI\s0 on oVirt or \s-1RHV\s0  
  .IX Item "UEFI on oVirt or RHV"
  Supported since oVirt/RHV ≥ 4.2 and virt-v2v ≥ 1.39.12.
